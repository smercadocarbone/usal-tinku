## Lo que se verificó y anda (contrastado UI vs API)

- Login por API y por UI; redirige a `/cuenta/reservas`.
- Búsqueda de texto libre, filtros de nivel/materia/precio máx. (inclusivo) y orden (relevancia, menor precio, mejor calificados): UI == API (mismos tutores, mismo orden, mismo precio; "Próximo horario" 12:00 UI = 15:00Z API). Orden "Menor precio" verificado ascendente en 24 resultados.
- "Tutor nuevo": con menos de 5 calificaciones (0, 3, 4) no se muestra promedio, ni en la tarjeta ni en el perfil; con 6+ sí (FR-REP-007). Coincide con la API (`calificacionPromedio: null`).
- Estado vacío con filtros ("Todavía no hay tutores con esos filtros" + "Sacar los filtros").
- Validaciones de búsqueda: sin criterios 422; nivel inválido 400; precio <=0 400; texto >500 caracteres 400; XSS/SQL en el texto sin efecto.
- Perfil del tutor (foto, bio, verificaciones, disponibilidad, precio, "Reservar clase").
- Reserva (API y UI): 30 min ($7.500), 1 h ($15.000), 90 min ($13.500) y 3 h ($27.000) con un tutor de franjas largas; duración 45/0 -> 422; fuera de franja o no alineado a 30 -> 422; tutor inexistente 404.
- Ventana mínima de 30 min medida al segundo: pedido a 30:05 de la clase -> 201; a 29:55 -> 422 (FR-RES-013). En la UI los bloques dentro de la ventana salen deshabilitados.
- Horario ocupado: mismo bloque y bloque solapado de otro alumno -> 409 `HORARIO_OCUPADO`; bloque contiguo -> 201; mismo alumno con dos tutores a la misma hora -> 409. Si el horario se ocupa mientras el alumno confirma en la UI, vuelve al paso 1 con "Ese horario se acaba de ocupar. Elegí otro.".
- Timeout de pago: `pendiente_pago` pasó a `cancelada/timeout_pago` a las 14:37:51 (vencía 14:37:48); el slot volvió a quedar libre; `/pagar` muestra "El tiempo para pagar se agotó..."; generar preferencia sobre ella -> 422.
- Cancelar una reserva pendiente: API y UI (modal "Todavía no pagaste, así que no se te cobra nada"); segunda cancelación 422; ajena 403.
- Calificar (solo negativos): estrellas 0/6/vacío -> 422; duplicada -> 422; ajena -> 403; editar fuera de las 48 hs -> 422.
- Resumen apagado: `adicional-resumen` devuelve `disponible:false`, `resumenContratado:true` -> 422 "todavía no está disponible", la UI no muestra el checkbox y el detalle de clase no ofrece resumen. `GET /sesiones/{id}/resumen` -> `disponible:false`; de otro alumno -> 403.

## No probado y por qué

- **Pago**: `POST /api/pagos/preferencia` devuelve `bypass:false` y una preferencia real de MercadoPago (`initPoint` real). No se pagó (regla del plan). Quedan sin probar: confirmación del pago, reserva `confirmada`, webhook y conciliación. Se generó una preferencia en MP sobre la reserva d43136b1 (ya vencida).
- **Cancelar una reserva confirmada (24 hs, reembolso total/parcial) y reprogramar** (T-60 min, conservar el pago): requieren una reserva `confirmada`; solo se probó que reprogramar una pendiente da 422 "Solo se puede reprogramar una Reserva confirmada.".
- **Calificar con éxito, editar dentro de las 48 hs, moderación del comentario, recordatorio**: las sesiones finalizadas más recientes de las 12 cuentas de estudiante (unas 80, las últimas 4 a 6 de cada una) ya estaban calificadas, y no se puede terminar una sesión nueva sin pago ni aula en vivo. Solo se probaron los rechazos.
- **Resumen encendido** (checkbox, precio, estado "disponible"): la función está apagada en producción; solo se verificó la parte "apagada".
- Paquete mensual: `paquete/oferta` devuelve `disponible:false` para el tutor probado.
- Aula, kill-switch, menores y Adulto Responsable (T3), móvil/accesibilidad (T7), rutas protegidas y roles cruzados (T6). Del lado T6 solo se anotó que sin token da 403 y no 401.
